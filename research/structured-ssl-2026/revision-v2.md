# V2：独立对象目标与结构化支持验证

这是 2026-10-03 对 v1 的机制修正，尚无 v2 完整准确率。v1 固定实验使用
封存的 `source-primary` 等源码继续运行。已完成六轮时，best 验证为
9972/14000 = 71.2286%，第六轮为 9762/14000 = 69.7286%；同平台冻结
anchor 为 10012/14000 = 71.5143%。v1 的容量和损失下降没有满足性能要求。

## SSL contribution

保留 Object-centric LeJEPA 的三层 masked mean → masked cross-attention →
FFN 聚合、可训练像素 Transformer，以及 Causal-JEPA 启发的完整对象
遮挡和固定教师目标。保持原单向五格预测第六格任务，答案候选不进入适配。

修正对象目标的输入：逐对象保留原包围框内像素，框外填白，再独立经过
冻结的原 CNN，按原区域 mask 池化。教师分批处理最多128个有效对象；
无效槽直接为零。空间位置、尺度不重新归一化；目标不等于独立语义属性。
框内相交对象仍可能混入，轮廓提案不是对象发现的证明。整格 dense target
保持原空间，不移动教师，不新增坍塌损失，也不改成双向任务。

## SER-PaV contribution

保留 SHINE 启发的三层支持记忆、每层48个 token、四层交替 depth/token
attention、三阶段 rank8 的 P/G/V 参数生成。每阶段同时预测查询缺格与
支持末格。修正验证和反馈的信息：

1. 在32通道归一化空间保留25个位置的局部残差，以及全局均值特征的
   归一化残差，组合成25个64维误差 token；不把位置误差先平均掉。
2. 用与评分相同的十步 Sinkhorn transport 对齐十个支持对象，在预测槽
   顺序中保留外观32维、几何6维、存在概率1维，共十个39维误差 token。
   空目标仅产生存在概率反馈，不引入无意义的外观/几何误差。
3. 两套线性映射把误差 token 投影到96维。查询状态作 attention query，
   支持预测状态作 key，误差作 value。得到与当前 query 相关的反馈，
   再通过 G 门控及 V 变换更新下一阶段；P仍负责支持条件预测修正。
   无偏置 value/attention 保证误差全零时反馈精确为零。

共2,270,454个可训练参数，比 v1 增加87,552个；冻结958,345个。实际使用
attention，没有实现 Mamba。P/G/V 是计算分工，不能直接称为语义规则。

## 已验证与未验证

- CPU/Metal 合成检查：全部可训练参数有限梯度、候选重排、对象重排、
  隐藏第六格边界、输入不变、教师不变、空对象，以及激活重计算一致性。
- 四个已记录的真实验证干预：v1外观目标相对变化为10.84%、7.63%、
  21.53%、12.47%；v2四例均逐位不变。仅证明框外隔离，不解释全部退步。
- 相同空间均值但不同位置的反例，新局部残差非零；对象目标重排不改变
  对齐反馈，空目标只贡献占用误差，零误差给零反馈。
- 结果收集器以合成封存文件检验完整六项聚合、三种子统计、共享原版
  对照，以及验证拒绝后的空 test 字段与 checkpoint 完整性。

上述均不能替代 v2 的真实 batch128 Metal 预检、完整训练/验证/测试和
贡献消融。性能不掉及两个独立贡献的收益仍未得到证明。

## 新实验封存与运行

`queue_revision.py` 在等待前封存全部新源码与两个消融导出，执行三项
CPU预检。待 v1 固定队列完成后，核验旧记录；共享相同源码/种子/预算的
已完成原版16轮对照，明确记录不重新训练。随后执行 v2 真实 batch128
Metal预检，再按固定顺序运行主种子12345、无遮挡对照、静态参数对照、
主种子12346、主种子12347，各8轮。三种子共享同一个指定 anchor。

各模型选择预算仍44轮，实际参数 lineage 单列。共享原版对照仍使用
候选负例，v2适配不使用；这种数据使用差异仍披露。第一轮优化前必须
复现完整同平台 anchor 验证。主模型验证门槛失败只推迟测试，不伪造测试
结果。所有结构、超参数和种子在这次测试前已锁定。既有测试记录不能
用于改动这份封存设计。新模型实际收益须从真实 best/final、七布局、
同容量消融及三种子结果判断。关闭新增分支不能当作贡献有效。
